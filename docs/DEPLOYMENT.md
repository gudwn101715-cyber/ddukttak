# 창작물 실행·공개·백업 안내

AI 창작 스튜디오를 실행하는 것과 완성한 작품을 공개하는 것은 다른 작업입니다. **스튜디오는 개인 작업 공간으로 유지하고, 공개할 작품의 HTML만 내보내는 방법**을 권장합니다.

## 1. 작품을 직접 플레이하고 확인하기

생성 직후 아래 동작을 확인합니다.

- 게임: 시작·조작·점수·실패 또는 승리·다시 시작이 동작하는지 확인합니다.
- 이야기: 각 선택지와 결말, 처음으로 돌아가기를 확인합니다.
- 시뮬레이션·아트·도구: 슬라이더·입력·버튼이 실제 결과에 반영되는지 확인합니다.
- PC와 휴대전화 크기에서 글씨와 터치 버튼을 확인합니다.
- 수정한 뒤에는 원래 동작도 다시 확인합니다. 필요하면 저장된 이전 버전으로 복원합니다.

실행 오류가 감지되면 오류 안내를 읽고 **AI로 이 오류 수정**을 요청할 수 있습니다. 실제 OpenAI 연결이 필요하며 요청마다 비용이 발생할 수 있습니다. 오류 안내가 사라졌다는 사실만으로 모든 기능이 올바르다고 판단하지 말고 다시 플레이하세요.

현재 작품은 단일 브라우저에서 실행되는 결과물입니다. 외부 데이터 요청·라이브러리 다운로드는 실행 정책에서 제한됩니다. 실시간 멀티플레이, 결제, 공유 데이터베이스, APK·iOS 패키징이 준비되었다는 뜻은 아닙니다.

## 2. HTML로 내려받아 실행하기

작품의 **실행 파일 받기** 또는 **실행 안내 → HTML 실행 파일 받기**로 파일을 받습니다. 일반 브라우저에서 파일을 열면 스튜디오 서버 없이 작품을 실행할 수 있습니다. API 키·OpenAI 연결 기능은 이 파일에 포함하지 않습니다.

내려받은 파일은 해당 시점의 복사본입니다. 스튜디오에서 수정해도 예전에 내려받거나 공유한 파일은 자동으로 바뀌지 않으므로 최신 파일을 다시 내려받아 교체하세요.

관리형 클라우드 브라우저가 `file://`를 차단하는 경우 파일 직접 열기는 제한될 수 있습니다. 이 환경의 자동 테스트는 다운로드 HTML의 바이트를 그대로 정적 HTTP 응답으로 제공해 동작을 검사합니다. 개인 컴퓨터의 브라우저에서 파일로 여는 것도 별도로 확인하세요.

## 3. 인터넷에 작품 공개하기

1. 공개할 작품을 HTML로 내려받습니다.
2. 새 폴더를 만들고 파일명을 **`index.html`**로 바꿔 넣습니다.
3. 본인의 정적 호스팅 계정에 로그인해 폴더를 업로드합니다.
4. 호스팅 서비스가 발급한 HTTPS 주소를 PC·휴대전화에서 엽니다.
5. 수정한 작품을 공개할 때는 같은 호스팅 사이트에 최신 파일을 다시 올립니다.

다음 공식 안내를 참고할 수 있습니다.

- [Cloudflare Pages Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/)
- [Netlify 수동 배포](https://docs.netlify.com/deploy/create-deploys/#deploy-manually)

호스팅 계정·도메인·공개 주소는 사용자가 직접 준비해야 하며 자동으로 생성하지 않습니다. 무료 이용 범위와 트래픽·파일 크기 제한은 선택한 서비스의 정책을 확인하세요.

설치 없는 스튜디오 체험 파일도 정적 호스팅할 수 있습니다. 다만 방문자의 작업은 각자 브라우저에 저장되고, 정적 호스팅만으로 실제 AI가 연결되지는 않습니다. API 키를 HTML 안에 넣거나 공개하면 안 됩니다.

## 4. 전체 창작 스튜디오 다시 실행하기

Node.js 22 이상을 준비합니다. 처음 설치한다면 Node.js 24 LTS를 권장합니다. Windows·macOS 실행 도우미는 [결과 보기 안내](VIEW_RESULT.md)에 있습니다. 직접 실행할 때는 프로젝트 폴더에서 다음 명령을 사용합니다.

```bash
npm ci
npm run dev
```

개발 화면의 기본 주소는 `http://localhost:5173`이며 API 서버는 `3001`에서 실행됩니다. 빌드한 화면과 API를 함께 제공하려면 다음을 실행합니다.

```bash
npm run build
npm start
```

기본 실행 주소는 `http://localhost:3001`입니다. 터미널은 사용 중 열어 두고 종료하려면 `Ctrl+C`를 누릅니다. `dist`만 정적 호스팅에 올리면 작품 API나 OpenAI 연결 서버가 없으므로 전체 제작 기능이 동작하지 않습니다.

기본 서버는 `HOST=127.0.0.1`, `PORT=3001`을 사용합니다. 개인 작업용 서버에 인증·사용자별 소유권 기능이 없으므로 인터넷에 직접 노출하지 마세요. 개발 프록시가 필요하면 인증된 비공개 경로를 사용하고 `.env.example`의 정확한 출처 설정 안내를 따릅니다. 허용 출처 목록을 추가하는 것만으로 사용자 인증이 생기지는 않습니다.

## 5. OpenAI 키 연결과 해제

전체 버전의 연결 화면에서 본인 키를 넣고 테스트하거나 서버의 `.env`에 `DDUK_AI_API_KEY`를 설정합니다. 기본 모델은 `gpt-4.1`이며 `DDUK_AI_MODEL` 또는 연결 화면에서 바꿀 수 있습니다. OpenAI API 기본 주소는 `https://api.openai.com/v1`입니다.

화면 입력 키는 실행 중인 서버 메모리에만 보관하고 서버 재시작 시 사라집니다. 화면에서 연결을 해제해도 `.env`의 키가 자동으로 삭제되지는 않습니다. 환경변수 키까지 없애려면 실행 환경의 해당 값을 제거한 뒤 서버를 다시 시작하세요. 작업 백업에 `.env`를 포함하지 말고 비밀값은 별도로 관리합니다.

AI 요청에는 사용자 설명과 현재 작품 코드가 전달됩니다. 작품 코드·대화에도 키나 비밀번호를 적지 마세요. API 요청 실패 시 원래 작품은 유지되며 예제로 자동 대체하지 않습니다. 연결 상태·모델 권한·요금과 공급자의 오류 안내를 확인한 뒤 다시 요청합니다.

## 6. 작업 데이터 보관하기

| 실행 방식 | 저장 위치 |
| --- | --- |
| 전체 버전의 창작 스튜디오 | 서버의 `.data/works.json` |
| 기존 웹사이트 구성형 빌더 | 서버의 `.data/workspace.json` |
| 설치 없는 체험 파일 | 해당 브라우저의 로컬 저장소 |

전체 버전은 서버를 중지한 후 `.data` 폴더 전체를 접근이 제한된 안전한 위치로 복사합니다. 복구할 때도 서버를 중지하고 기존 데이터를 별도 보관한 뒤 백업을 원래 위치로 돌려놓습니다. 화면을 다시 빌드하는 것만으로 데이터가 복구되지는 않습니다.

체험 파일은 서버 백업이 없습니다. 브라우저 데이터를 지우기 전에 필요한 작품을 HTML로 내려받으세요. HTML은 실행 결과물이고 스튜디오의 전체 대화·버전 백업과는 다릅니다. **실행 안내 → 작업 원본 JSON 백업**으로 대화·코드·버전이 포함된 원본도 보관할 수 있지만 현재 화면에서 JSON을 자동으로 다시 불러오는 기능은 없습니다. 다른 브라우저나 파일 위치로 옮기면 기존 작업을 찾지 못할 수도 있습니다.

## 기존 웹사이트 빌더 결과물을 사용할 때

기존 빌더의 예약·문의·구독 양식은 방문자 브라우저에만 저장되는 체험용 기능입니다. 실제 사업자에게 전송되거나 예약이 확정되지 않으며 별도의 수신 서비스가 필요합니다. 로컬 게시 경로도 현재 서버가 켜져 있을 때 사용하는 경로이며 인터넷 공개 도메인 발급 결과가 아닙니다. 사진·FAQ·후기 편집과 공개 전 확인은 [기존 빌더 안내](WEBSITE_BUILDER.md)를 참고하세요.

## 문제가 생기면

| 증상 | 확인할 내용 |
| --- | --- |
| HTML 체험 파일에서 AI가 연결되지 않음 | 예제 전용 파일입니다. 전체 버전을 실행하고 OpenAI 연결 사용 |
| 전체 버전이 열리지 않음 | Node.js 버전, 실행 창 오류, 실제 표시된 포트 확인 |
| 연결 테스트 실패 | API 키 유효성, API 결제·모델 권한, 인터넷·공급자 접근 확인 |
| AI가 요청한 기능을 다 만들지 못함 | 한 번에 한 기능씩 구체적으로 수정하고 실행 결과 확인 |
| 작품 실행 중 오류 | 오류 내용 확인 후 실제 AI 오류 수정 또는 이전 버전 복원 |
| 다른 사람이 로컬 주소를 열 수 없음 | 로컬 주소는 인터넷 주소가 아님. 작품 HTML을 정적 호스팅에 업로드 |
| 작업이 사라짐 | 서버의 같은 `.data` 폴더인지, 체험판의 같은 브라우저인지 확인 |

문제 자료를 공유할 때는 키·개인정보를 제거하고 사용한 실행 방식, 오류 메시지, 해당 동작을 함께 알려 주세요.
