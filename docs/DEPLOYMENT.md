# 만든 웹사이트를 실제로 사용하기

제작 도구를 켜는 것과 만든 사이트를 인터넷에 공개하는 것은 서로 다른 작업입니다. 이 안내에서는 먼저 결과물을 직접 실행하고, 그다음 필요한 경우 공개 주소를 얻는 방법을 설명합니다.

## 1. 공개 전 직접 확인하기

제작 화면에서 다음을 확인합니다.

- 이름, 소개, 연락 안내가 실제 서비스에 맞는지 확인합니다.
- 갤러리 사진·설명, FAQ 답변, 고객 후기를 실제 내용으로 바꿉니다. 예시 후기는 삭제하거나 후기 기능을 끕니다.
- 데스크톱·모바일 미리보기에서 글씨와 버튼을 확인합니다.
- 문의·예약 폼에 입력해 보고 필수 항목 검증이 작동하는지 확인합니다.
- 자동 점검을 실행하고 주의 항목을 읽습니다.
- 이전 버전과 비교하고 필요하면 복원합니다.

폼에 정보를 넣어도 사업자에게 전송되지는 않습니다. 현재 버전은 입력을 해당 브라우저에 보관하는 방식입니다. 실제 고객 문의나 예약을 받기 전에는 데이터 수신 서버, 사업자 알림, 개인정보 안내를 연결해야 합니다. 미리보기에 접수 완료 메시지가 나오는 것만으로 실제 예약이 확정되는 것은 아닙니다.

## 2. 내 컴퓨터에서 바로 열기

제작한 프로젝트에서 **실행하기 → 실행 안내 → 앱 파일 내려받기**를 선택합니다. 내려받은 `.html` 파일을 두 번 클릭하면 브라우저에서 열립니다. 파일에 필요한 스타일과 실행 코드가 함께 들어 있으므로 별도의 Node.js 설치나 빌드가 필요하지 않습니다.

이 파일은 내려받은 시점의 복사본입니다. 제작 화면에서 수정한 내용이 자동으로 반영되지는 않습니다. 변경한 뒤에는 최신 파일을 다시 내려받으세요.

**내 사진 올리기**로 넣은 사진은 크기가 줄어든 JPEG 형태로 HTML에 포함됩니다. 사진 주소를 직접 입력한 경우에는 원본 사진이 파일에 포함되지 않으며, 인터넷 연결이 있어야 불러올 수 있습니다. 외부 공개 전에는 공개 주소에서 사진이 실제로 보이는지도 확인하세요.

브라우저에 따라 파일로 연 화면의 저장소 사용이 제한될 수 있습니다. 폼 입력 내용은 브라우저·기기 간에 공유되지 않으며 저장소를 지우면 사라집니다. 영구적인 고객 데이터 저장소로 사용하지 마세요.

관리형 클라우드 브라우저처럼 `file://` 접근이 차단된 환경에서는 파일을 직접 열 수 없을 수 있습니다. 이 환경의 자동 테스트는 내려받은 HTML을 변경 없이 정적 HTTP로 제공해 화면과 폼 동작을 확인합니다. 직접 파일 열기는 사용하는 컴퓨터의 브라우저에서도 확인해 주세요.

## 3. 현재 서버에서 실행본 만들기

프로젝트의 **실행 안내 → 로컬 페이지 게시**를 누르면 현재 서버의 `/published/…` 경로가 발급됩니다. **게시된 페이지 열기**로 결과물을 확인할 수 있습니다. 서버가 켜져 있어야 열립니다.

이 경로는 인터넷 도메인이나 클라우드 배포를 자동으로 생성한 결과가 아닙니다. 현재 서버에 접근할 수 있는 환경에서만 열립니다. 서버를 중지하면 응답하지 않습니다.

실행본은 게시 시점의 버전을 보관합니다. 편집 중인 초안은 실행본을 다시 만들기 전까지 반영되지 않으므로, 작업 도중에도 현재 실행본을 유지할 수 있습니다.

## 4. 인터넷에 사이트 공개하기

외부 호스팅 계정이 있으면 내려받은 정적 HTML을 업로드해 실제 공개 주소를 받을 수 있습니다. 이 프로젝트가 호스팅 계정을 자동으로 만들거나 도메인을 구입하지는 않습니다.

### Cloudflare Pages 사용 예시

1. 결과물 HTML을 내려받습니다.
2. 컴퓨터에 빈 폴더를 만들고 파일을 넣습니다. 파일 이름을 `index.html`로 바꿉니다. 기존 파일이 있는 폴더를 사용하지 마세요.
3. Cloudflare 대시보드에 로그인하고 **Workers & Pages**에서 Pages 프로젝트를 만듭니다.
4. 정적 파일을 직접 업로드하는 방식을 선택하고 해당 폴더 또는 지원되는 압축 파일을 올립니다.
5. 배포가 끝나면 호스팅 서비스가 발급한 HTTPS 주소를 엽니다.
6. 내 휴대전화에서도 주소를 열어 내용과 버튼 동작을 다시 확인합니다.

대시보드의 메뉴명은 서비스 업데이트에 따라 달라질 수 있습니다. 최신 절차는 [Cloudflare Pages Direct Upload 공식 안내](https://developers.cloudflare.com/pages/get-started/direct-upload/)를 참고하세요.

### Netlify 사용 예시

1. `index.html`이 들어 있는 새 폴더를 준비합니다.
2. Netlify에 로그인하고 수동 배포 기능에서 폴더를 업로드합니다.
3. 배포가 끝나면 발급된 HTTPS 주소를 확인합니다.
4. 수정한 경우 같은 사이트에 최신 결과물을 다시 업로드합니다.

최신 절차는 [Netlify 수동 배포 공식 안내](https://docs.netlify.com/deploy/create-deploys/#deploy-manually)를 참고하세요. 무료 이용 범위, 트래픽·파일 제한, 도메인 비용은 선택한 호스팅 서비스의 정책을 확인해야 합니다.

외부 호스팅에 올려도 브라우저 안에서만 저장되는 폼이 자동으로 서버 폼으로 바뀌지는 않습니다. 실제 고객 데이터를 받으려면 별도 연동이 필요합니다.

## 제작 도구를 다시 실행하기

Node.js 22 이상이 설치된 컴퓨터에서 프로젝트 폴더를 열고 실행합니다.

```bash
npm ci
npm run build
npm start
```

기본적으로 빌더와 API가 `127.0.0.1`의 `3001` 포트에서 실행됩니다. `HOST`와 `PORT`로 변경할 수 있지만, 인증이 없는 상태에서 서버를 외부에 공개하지 마세요. `dist`는 제작 화면의 빌드 결과물이며, 프로젝트 데이터는 `.data/workspace.json`에 별도로 저장됩니다. `dist`만 정적 호스팅에 올리면 프로젝트 API가 없어 제작 기능은 동작하지 않습니다.

개발을 이어갈 때는 다음 명령을 사용합니다.

```bash
npm run dev
```

AI를 연결하려면 프로젝트 루트의 `.env`에 서버 전용 환경변수를 설정하고 프로세스를 다시 시작합니다. 기존 `.env` 파일과 키를 덮어쓰지 마세요. 실행 환경의 비밀값 저장 기능을 사용할 수 있다면 그곳에서 주입하는 방법을 권장합니다.

## 작업 데이터 백업하기

서버가 중지된 상태에서 프로젝트의 `.data` 폴더 전체를 접근이 제한된 안전한 위치로 복사합니다. 프로젝트 구성과 수정 이력, 실행본 메타데이터가 들어 있으므로 작업에 맞게 보관하세요. 버전 관리 저장소에 고객 정보나 `.env`를 올리지 마세요.

복구할 때는 서버를 중지한 후 기존 데이터를 별도 보관하고, 백업한 `.data`를 원래 위치로 복사한 다음 다시 실행합니다. 프런트엔드를 다시 빌드하는 것만으로 프로젝트 데이터가 복구되지는 않습니다.

## 제작 플랫폼을 공개 서비스로 운영하려면

현재 구현은 한 사람이 사용하는 로컬 작업실입니다. 인증 없이 프로젝트를 관리하는 API를 그대로 인터넷에 노출하면 접근 가능한 다른 사람이 프로젝트를 읽거나 바꾸거나 지울 수 있습니다. 다음 항목이 추가된 뒤 공개 서비스로 운영하세요.

| 준비 항목 | 필요한 이유 |
| --- | --- |
| OAuth와 사용자별 소유권 확인 | 다른 사용자의 프로젝트 조회·수정 차단 |
| 관리형 데이터베이스·백업 | 다중 인스턴스 저장, 장애 복구, 데이터 보존 |
| 비밀값 관리와 사용량 제한 | AI 키 보호, 과금·남용 제어 |
| 호스팅 API·별도 생성물 도메인·HTTPS | 생성 앱과 빌더 분리, 실제 공개 주소 제공 |
| 데이터 수신·알림·삭제 기능 | 실제 문의·예약 처리와 사용자 데이터 관리 |
| 운영 모니터링 | 생성·배포 실패 파악과 장애 대응 |

위 항목은 TRD에 제시된 상용 아키텍처의 후속 연동 작업입니다. 현재 API의 로컬 실행본이나 내려받기 기능을 이 연동이 완료된 것으로 해석하지 마세요.

## 문제가 생겼을 때

| 증상 | 확인할 내용 |
| --- | --- |
| 제작 화면이 열리지 않음 | 터미널에서 실행 명령이 계속 동작하는지, 안내된 포트가 맞는지 확인 |
| 메뉴까지 보이지 않고 `504 Outdated Optimize Dep`가 나타남 | 개발 서버를 종료하고 `npm run dev`로 다시 시작한 뒤 미리보기를 다시 열기. 현재 명령은 시작할 때 개발 캐시를 새로 만듦. 브라우저의 작업 데이터는 지울 필요 없음 |
| 새 프로젝트를 누르면 화면이 비거나 임시 초안이 불완전함 | 현재 버전은 저장된 초안을 검증하고 유효한 답변을 복구함. 손상된 원본은 브라우저의 별도 `ddukttak-draft-recovery` 항목에 보관하며 서버 프로젝트는 삭제하지 않음 |
| 화면은 열리지만 프로젝트를 불러오지 못함 | API 서버가 시작되었는지 확인. 개발 모드는 `npm run dev`로 두 프로세스 실행 |
| AI 요청 실패 | 키 설정 여부, 모델 권한, 지원하는 출력 형식, 네트워크 확인. 키 값은 공유하지 않기 |
| 수정 요청이 적용되지 않음 | 기본 모드 지원 문구로 요청하거나 편집 도구 사용. 실패 안내 뒤에는 이전 구성 유지 |
| 다른 기기에서 로컬 실행본이 열리지 않음 | 로컬 주소는 인터넷 공개 주소가 아님. 정적 HTML을 외부 호스팅에 업로드 |
| 새 배포에 이전 내용이 표시됨 | 최신 HTML을 다시 내려받아 같은 호스팅 사이트에 업로드했는지 확인 |
| 저장한 프로젝트가 사라짐 | 같은 `.data` 폴더를 사용하는지 확인. 삭제한 폴더는 백업에서 복구 |

문의할 때는 실행한 명령, 오류 메시지, 사용한 화면을 알려 주세요. API 키와 개인정보는 오류 자료에서 제거하세요.

신뢰하는 프록시 주소에서 개발 화면을 열어야 한다면 `.env.example`의 `DDUK_ALLOWED_ORIGINS`에 실제 HTTPS 출처를 정확하게 지정하고 `npm run dev`를 재시작하세요. 같은 설정이 개발 화면의 호스트와 API 요청 출처에 적용됩니다. 주소를 모르는 상태에서 임의의 호스트나 와일드카드를 넣지 마세요. 이 설정만으로 다중 사용자 인증이나 인터넷 공개 운영이 준비되는 것은 아닙니다.
