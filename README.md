# 무엇이든 뚝딱

아이디어를 적고 몇 가지 질문에 답하면, 직접 눌러 볼 수 있는 웹사이트가 만들어지는 제작 도구입니다. 코드를 몰라도 기능을 추가하고, 문구와 색을 수정하고, 이전 모습으로 돌아갈 수 있습니다.

이 버전은 **한 사람이 사용하는 로컬 제작 작업실**입니다. 외부 계정 없이도 기본 생성·수정·미리보기·파일 내려받기를 사용할 수 있습니다. AI API를 연결하면 자유로운 자연어 요청을 처리하고, 연결하지 않으면 지원하는 템플릿과 수정 규칙으로 동작합니다.

## 결과물부터 보는 방법

GitHub에서 **Code → Download ZIP**으로 이 브랜치를 내려받아 압축을 풀고, **`preview/index.html`**을 Chrome 또는 Edge로 열면 설치 없이 제작 화면을 체험할 수 있습니다. [파일 열기 안내](preview/README.md)를 참고하세요.

별도로 제공되는 `ddukttak-preview.html`은 서버 없이 제작 화면과 기본 기능을 체험하는 파일입니다. 프로젝트는 해당 브라우저에 저장되며 실제 AI·응답 수집 서버에는 연결하지 않습니다. [설치 없는 체험과 전체 버전 실행 안내](docs/VIEW_RESULT.md)를 먼저 확인하세요.

소스에서 체험용 파일을 다시 만들려면 의존성 설치 후 `npm run build:portable`을 실행하세요. `artifacts/ddukttak-preview.html`에 화면·스타일·글꼴이 포함된 단일 HTML이 만들어집니다.

## 시작하기

컴퓨터에 Node.js 22 이상과 npm이 필요합니다. [Node.js 공식 사이트](https://nodejs.org/)의 LTS 버전을 설치해도 됩니다.

프로젝트 폴더에서 터미널을 열고 실행합니다.

```bash
npm ci
npm run dev
```

터미널에 표시되는 Vite 주소로 접속합니다. 기본 개발 주소는 `http://localhost:5173`이며, API 서버는 별도로 `3001` 포트에서 실행됩니다. 개발 명령 한 번으로 두 프로세스가 함께 시작됩니다. 종료할 때는 터미널에서 `Ctrl+C`를 누릅니다.

AI 키나 호스팅 계정은 기본 사용에 필요하지 않습니다. 다른 사람이 인터넷에서 접속할 수 있는 주소가 필요하다면 아래의 [실행·공개 안내](docs/DEPLOYMENT.md)를 참고하세요.

## 처음 앱을 만드는 순서

1. **새 프로젝트 만들기**를 누르거나, 원하는 템플릿을 선택합니다.
2. 제작할 웹사이트 종류와 이름, 소개를 입력합니다. 예: “동네 요가 수업을 소개하고 예약 신청을 받는 사이트”.
3. 원하는 디자인과 기능을 고릅니다. 문의, 예약 신청, 갤러리, 자주 묻는 질문, 소식 구독, 후기 등을 조합할 수 있습니다.
4. 생성 후 미리보기에서 버튼을 눌러 보고, 모바일 화면도 확인합니다.
5. 수정 대화창에 원하는 변경을 적거나, **직접 수정**에서 문구와 테마를 바꿉니다. **디자인 세부 설정**에서 배경·글꼴·모서리를, **페이지 소개 영역 수정**에서 각 소개 영역의 제목과 설명을 바꿀 수 있습니다. 소개 영역도 추가하거나 삭제할 수 있습니다. 갤러리·FAQ·후기 기능을 켜면 같은 창에서 실제 사진과 설명, 질문·답변, 후기 내용과 이름도 편집할 수 있습니다.
6. **실행하기 → 실행 안내**에서 자동 점검을 확인한 뒤 **앱 파일 내려받기** 또는 **로컬 페이지 게시**를 선택합니다.

아직 만들기를 완료하지 않은 답변과 질문 단계도 같은 브라우저에 임시 저장됩니다. 다시 **새 프로젝트 만들기**를 누르면 이어갈 수 있습니다. 새 템플릿이나 새로운 아이디어로 시작하면 새 흐름으로 진행합니다.

생성한 프로젝트와 수정 이력은 서버의 `.data/workspace.json`에 저장됩니다. 브라우저를 새로고침하거나 서버를 다시 켜도 같은 프로젝트 폴더에서 실행하면 이어서 작업할 수 있습니다. `.data`를 지우면 저장한 프로젝트도 사라지므로 별도로 보관하세요.

## 수정은 이렇게 요청하세요

AI를 연결하지 않은 기본 모드에서는 지원하는 변경을 구체적으로 적어 주세요.

```text
테마를 파란색으로 바꿔 줘
제목을 '매일의 작은 쉼, 우리 동네 요가'로 바꿔 줘
버튼 문구를 '수업 문의하기'로 바꿔 줘
자주 묻는 질문을 추가해 줘
갤러리를 삭제해 줘
```

지원하지 않는 요청은 변경이 적용되지 않았다는 안내가 표시됩니다. 편집 도구에서 가능한 설정을 직접 바꾸거나 AI를 연결해 다시 요청할 수 있습니다. 수정할 때마다 이력이 남으며, 이전 버전을 복원해도 현재 작업을 덮어 지우는 대신 새 버전이 만들어집니다.

## 만들 수 있는 것

| 기능 | 현재 제공 범위 |
| --- | --- |
| 단계별 앱 생성 | 소개 페이지, 예약 소개, 포트폴리오, 상품 소개 등 검증된 구성 조합 |
| 실시간 미리보기 | 데스크톱·모바일 크기, 격리된 iframe에서 버튼·폼 실행 |
| 기능 추가와 수정 | 구성 요소 켜기·끄기, 문구·테마 편집, 소개 영역 추가·삭제, 자연어 요청 |
| 실제 콘텐츠 편집 | 사진 업로드·HTTPS 사진 주소, 갤러리 설명, FAQ 질문·답변, 후기 내용·이름 편집 |
| 자동화 | 구성 생성, 수정 버전 기록, 준비 상태 자동 점검, 정적 HTML 생성 |
| 버전 복원 | 저장된 구성으로 새 버전 생성 |
| 결과물 사용 | 단독 실행 가능한 HTML 내려받기, 현재 서버에서 실행본 열기 |
| AI 연동 | 서버에 키를 설정한 경우 구조화된 JSON 생성·수정 |

예약·문의·소식 구독 폼은 화면에서 입력과 검증을 체험할 수 있습니다. 제출 내용은 **해당 브라우저에만 저장**되며 사업자에게 전송되지 않습니다. 샌드박스처럼 브라우저 저장소 사용이 제한된 화면에서는 현재 화면이 열려 있는 동안만 보관됩니다. 실제 예약 확정, 이메일 발송, 고객별 데이터 공유는 별도의 서버 연동이 필요합니다. 상품 소개 템플릿에도 실제 결제 기능은 포함되어 있지 않습니다.

자동 점검은 구성 유효성, 주요 요소, 게시 상태 등을 확인하는 보조 도구입니다. 외부 호스팅의 연결 상태나 실제 예약 처리까지 확인했다는 의미는 아닙니다. 완료 전에는 직접 미리보기에서 주요 동작을 확인하세요.

갤러리·FAQ·후기는 처음에 예시로 채워집니다. **직접 수정**에서 **갤러리 사진과 설명 수정**, **자주 묻는 질문 수정**, **고객 후기 수정**을 펼쳐 실제 내용으로 바꾸세요. 해당 항목이 보이지 않으면 먼저 **기능 관리**에서 기능을 추가합니다. 갤러리는 최대 6개, FAQ는 10개, 후기는 6개까지 추가·삭제할 수 있습니다. 실제 고객 후기가 없다면 예시를 공개하지 말고 후기 기능을 꺼 주세요.

사진은 한 장당 10MB 이하의 JPG·PNG·WebP를 올릴 수 있습니다. 업로드 시 브라우저에서 크기를 줄이고 JPEG로 변환해 앱 파일에 함께 저장하므로, 내려받은 HTML에서도 사진을 볼 수 있습니다. HTTPS 사진 주소를 대신 넣을 수도 있지만 해당 사진은 인터넷 연결과 원본 서버의 접근 허용이 필요합니다. 상세 사진·FAQ·후기는 직접 편집하며, AI로 다른 부분을 수정해도 이 내용은 보존됩니다. 이 상세 콘텐츠와 업로드한 사진은 AI 공급자에게 전송하지 않습니다.

## AI 연결하기 — 선택 사항

API 키는 브라우저에 넣지 않고 서버에서만 사용합니다. 새 설치에서는 `.env.example`을 참고해 프로젝트 루트에 `.env` 파일을 만듭니다. 기존 `.env`가 있으면 덮어쓰지 말고 필요한 항목만 추가하세요.

| 변수 | 용도 |
| --- | --- |
| `DDUK_AI_API_KEY` | AI 공급자에게 발급받은 API 키. 비워 두면 기본 모드로 동작 |
| `DDUK_AI_MODEL` | 공급자에서 사용할 수 있는 모델 이름. 기본값 `gpt-4.1` |
| `DDUK_AI_BASE_URL` | OpenAI 호환 API 기본 주소. 기본값 `https://api.openai.com/v1` |

설정 후 개발 서버를 다시 실행합니다. 사용 모델은 JSON Schema 기반의 Structured Outputs를 지원해야 합니다. 화면의 AI 설정 표시는 키가 등록되었다는 뜻이며, 실제 API 연결은 생성·수정 요청 때 확인됩니다. API 사용량에 따라 공급자 비용이 발생할 수 있습니다. 키를 채팅, 스크린샷, Git 저장소 또는 `VITE_` 환경변수에 넣지 마세요.

AI 요청에 실패해도 성공했던 프로젝트 구성은 유지됩니다. 연결 상태와 오류 안내를 확인한 뒤 키, 사용 가능한 모델, 네트워크 연결을 점검하세요.

## 빌드와 확인

```bash
npm test
npm run build
npm run test:e2e
npm start
```

`npm run build`는 TypeScript를 검사하고 프런트엔드를 `dist`에 생성합니다. `npm start`는 빌드한 화면과 API를 함께 제공합니다. 기본 실행 주소는 `http://localhost:3001`입니다.

`npm test`는 구성 검증·기본 생성과 수정·프로젝트 API·AI 오류 처리를 검사합니다. `npm run test:e2e`는 Chromium에서 생성, 샌드박스 격리, 양식 동작, 기능 변경, 버전 복원, 로컬 게시, 다운로드, 모바일 배치와 중간 답변 복구를 검사합니다. 이 명령은 필요한 개발 서버를 자동으로 시작하거나 이미 실행 중인 개발 서버를 사용합니다. AI 키가 없는 기본 제작 모드에서 실행하세요.

브라우저 테스트에는 Chromium이 필요합니다. 현재 클라우드에서는 `/usr/bin/chromium`을 사용하며, 다른 설치 경로는 실행 환경변수 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정할 수 있습니다. 시스템 Chromium이 없으면 `npx playwright install chromium`으로 Playwright용 브라우저를 설치한 뒤 실행하세요. 클라우드 브라우저가 `file://` 열기를 제한하므로 내려받은 HTML의 바이트를 그대로 정적 HTTP 응답으로 제공해 독립 실행을 검사합니다. 이 검사는 해당 클라우드에서 파일을 두 번 클릭하는 동작 자체를 검증한 것은 아닙니다.

실제로 검증해야 하는 흐름은 “생성 → 미리보기 조작 → 기능 추가 → 문구 수정 → 버전 복원 → 결과물 내려받기”입니다. 테스트·빌드 성공과 인터넷 공개 완료는 별개의 결과입니다. 상용 AI API의 실제 응답, 외부 호스팅, 다른 운영체제·브라우저는 해당 환경에서 별도로 확인해야 합니다.

## 구조

```text
src/                 React + TypeScript 제작 화면
src/lib/schema.ts    생성된 앱의 데이터 규격과 검증
src/lib/generator.ts  기본 생성·부분 수정 규칙
src/lib/renderer.ts   검증된 구성으로 정적 HTML 생성
server/              프로젝트 API, 파일 저장, AI 연결
docs/DEPLOYMENT.md    실행·백업·인터넷 공개 안내
.data/               실제 작업 데이터 — Git에 포함하지 않음
```

AI는 원시 HTML·JavaScript 대신 검증 가능한 앱 구성을 반환합니다. 렌더러가 정해진 구성 요소로 화면을 만들고, 미리보기는 부모 화면의 쿠키·저장소와 분리된 iframe에서 실행됩니다.

제작 도구의 화면 글꼴은 프로젝트 패키지에 포함되어 외부 폰트 CDN 없이 불러옵니다. 내려받는 HTML 결과물은 별도 폰트 다운로드가 필요 없는 시스템 글꼴을 사용합니다.

## 개발문서와 현재 버전의 차이

첨부 BRD·PRD·TRD를 바탕으로 제작 경험과 정적 앱 생성 흐름을 구현했습니다. 문서의 전체 상용 서비스 요건이 모두 완료된 버전은 아닙니다.

소셜 OAuth, 사용자별 권한, 관리형 PostgreSQL, 클라우드 배포 API, 고유 서브도메인 자동 발급, CDN, 결제, 운영 모니터링은 아직 연결되지 않았습니다. 반응형 웹은 제공하지만 앱스토어 등록이나 설치형 PWA의 오프라인 기능을 제공한다고 보장하지 않습니다. 현재 파일 저장 방식과 인증 없는 API는 개인 개발 환경을 위한 것입니다.

여러 사용자가 이용하는 공개 서비스로 운영하려면 [배포 안내의 플랫폼 운영 조건](docs/DEPLOYMENT.md#제작-플랫폼을-공개-서비스로-운영하려면)을 먼저 구현해야 합니다. 생성한 정적 웹사이트는 해당 안내의 파일 업로드 방식으로 별도로 공개할 수 있습니다.
